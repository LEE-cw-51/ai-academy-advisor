# 학원콕 반복 사용 루프 검토

**검토일:** 2026년 9월 22일
**상태:** 제품 전략 가설. 구현 전 고객 행동 검증 필요.

## 핵심 결론

학원콕의 반복성은 매일 방문하는 습관을 억지로 만드는 방식보다, 학부모가 학원과 아이의 학습 상태를 확인해야 하는 **주간·월간·사건 기반 순간**에 다시 사용하는 구조로 검증하는 편이 타당하다. 학원 선택은 본질적으로 저빈도·고관여 과업이므로, 목표를 DAU로 두면 불필요한 알림·콘텐츠·점수화 기능이 붙을 위험이 있다.

첫 번째 반복 루프의 이름은 가설상 **‘학부모 학습 점검’**으로 둔다. 학원이나 아이의 품질을 평가하지 않고, 지난 기간에 무엇을 확인했는지와 다음에 어떤 질문을 할지를 구조화한다.

## 반복 사용 후보 비교

| 후보 | 사용 순간 | 제공 가치 | 예상 빈도 | 초기 판단 |
|---|---|---|---|---|

| 시험·성적표 후 질문 정리 | 시험·평가·성적표를 받은 뒤 | 결과를 단정하지 않고 학원·아이에게 물을 질문 정리 | 월 1–2회 또는 시험 주기 | 1순위 |
| 학원 상담 준비·후속 기록 | 상담 전·상담 직후 | 질문 준비, 답변 기록, 미해결 항목의 다음 확인일 설정 | 월 1회~학기별 | 1순위 |

| 학원 정보 변경 알림 | 학원 운영정보가 바뀌었을 때 | 저장한 학원의 연락처·운영 정보 최신성 확인 | 낮음 | 데이터 품질 이후 |
| 교육 콘텐츠·지역 소식 | 평소 탐색 | 읽을거리와 재방문 이유 제공 | 주 1회 이상 | 보류 |
| 학부모 커뮤니티 | 평소 질문·경험 공유 | 동료 경험과 정서적 지원 | 높을 수 있음 | 보류 |

## 가장 유망한 핵심 루프

### 루프: 점검 → 질문 → 직접 확인 → 다음 점검

1. **Trigger:** 주말, 시험 결과, 숙제 반복 막힘, 학원 상담 예정, 아이가 학원에 대한 불편을 말한 순간에 사용자가 방문한다.
2. **Input:** 사용자는 자녀 실명·성적표·상세 자유서술 없이 선택형으로 현재 상황을 고른다. 예를 들면 `진도`, `오답`, `숙제`, `질문 대응`, `보강`, `학원과의 소통`, `아이의 적응`이다.
3. **Output:** 학원콕은 상태 점수나 학원 품질 판정 대신, `이번에 물어볼 질문`, `직접 확인할 사실`, `다음에 다시 볼 시점`을 만든다.
4. **Action:** 사용자는 질문을 복사하거나 다운로드해 아이·학원과 대화한다. 학원콕이 부모 연락처를 학원에 전달하거나 상담을 대신 접수하지 않는다.
5. **Feedback:** 사용자는 선택적으로 `확인함`, `답변을 받음`, `아직 미확인`만 표시한다. 답변 원문과 민감한 학습 기록은 기본 저장하지 않는다.
6. **Return:** 다음 시험·상담·점검 시 이전에 미확인으로 남긴 질문을 다시 확인할 수 있다.

이 루프의 제품 가치는 학원을 매일 평가하는 것이 아니라, 학부모가 **학습 블랙박스를 정기적으로 질문 가능한 상태로 바꾸는 것**이다.

## 기능 후보와 범위

### 1단계: 로그인 없는 점검 결과

상황 입력 후 결과에 `이번 점검에서 확인할 3가지`, `학원에 물어볼 질문`, `아이에게 물어볼 질문`, `다음 확인 시점`을 표시한다. 결과를 복사하거나 이미지·PDF로 저장하게 한다. 이 단계에서는 계정, 자녀 프로필, 점수표, 푸시 알림을 만들지 않는다.

### 2단계: 선택적 재방문

사용자가 직접 `다음 점검 링크 만들기` 또는 `내보내기`를 선택했을 때만 익명 재방문용 링크나 로컬 저장을 제공한다. 저장되는 정보는 학년대·과목·점검 항목·미확인 여부처럼 최소화한다. 자녀 이름과 성적을 요구하지 않는다.

### 3단계: 상담 후속 보드

반복 사용이 확인되면 `질문함 → 답변 받음 → 추가 확인 필요`의 세 칸만 제공한다. 답변 원문을 장기 저장하는 기능은 별도 동의와 개인정보 검토 전에는 넣지 않는다. 이 보드는 학원 평가나 별점이 아니라 부모의 의사결정 기록이다.

### 4단계: 선택형 알림

실제 재방문이 확인된 뒤에만 다음 시험·상담·점검 시점을 사용자가 직접 설정하게 한다. 기본값은 이메일·푸시가 아니라 캘린더 내보내기 또는 사용자가 요청한 리마인더로 둔다.

## 절대 피해야 할 반복성 전략

- 학원이나 아이를 주간 점수·등급·건강점수로 평가하는 기능
- 근거 없는 ‘이번 주 학습 상태’ 진단 또는 성적 예측
- 불안을 자극하는 매일 알림과 연속 방문(streak)
- 학원 후기를 매일 소비하게 만드는 커뮤니티를 먼저 구축하는 것
- 학원 정보가 없는 날에도 볼거리를 만들기 위한 일반 교육 콘텐츠 공장
- 반복 사용을 이유로 자녀 실명, 성적표, 상세 상담 원문을 기본 수집하는 것
- 학원에 질문·기록을 자동 전달해 리드 서비스로 변질하는 것

## 반복성 가설과 검증

| 가설 | 가장 싼 검증 | 관찰할 행동 | 초기 판단 기준 |
|---|---|---|---|
| 부모는 학원 선택 이후에도 학습 확인 질문을 반복해서 필요로 한다 | 학부모 8–10명에게 최근 30일의 학원·학습 확인 사건을 회고시키고 7일 미니 다이어리 실시 | 사건 발생, 현재 대안, 질문·확인 행동 | 3명 이상에게 같은 반복 사건이 발견되고 기존 대안의 불편이 설명됨 |
| 질문 카드가 실제 대화를 바꾼다 | 기존 `/app` 결과를 질문 카드 형태로 제공하는 수동 테스트 | 질문 복사·채택·편집, 아이·학원에 사용 | 참여자의 60% 이상이 질문 1개 이상을 실제 또는 예정 대화에 사용 |
| 점검 결과가 다음 재방문을 만든다 | 1주 간격으로 두 번 수동 발송 또는 링크 재사용 | 7일 내 두 번째 점검, 미확인 질문 재방문 | 최소 3명 이상이 자발적으로 두 번째 점검을 수행 |
| 기록 기능이 가치가 있다 | 답변 원문이 아닌 세 상태 보드 수동 제공 | 다음 상담에서 이전 미확인 항목을 다시 사용 | 3명 이상이 기록을 다음 행동에 활용 |
| 부모가 저장·알림을 원한다 | 반복 사용 후 선택지 인터뷰 | 링크 저장, 캘린더 추가, 알림 요청 | 자발적 요청이 있는 경우에만 구현 검토 |

## 4주 검증 순서

### 1주차: 반복 사건 조사

최근 30일 동안 학원·숙제·오답·질문·상담과 관련해 부모가 아이 또는 학원에 확인했던 순간을 8–10명에게 조사한다. “매일 쓸 것인가”를 묻지 않고 실제 날짜와 행동을 복원한다. 사건이 없는 사람은 반복성 표본에서 제외한다.

### 2주차: 수동 질문 카드

코드보다 먼저 상황별 질문 카드를 수동으로 제공한다. `시험 후`, `숙제·오답`, `질문 대응`, `보강`, `상담 전` 중 하나를 선택하게 하고, 질문을 실제로 복사하거나 사용했는지 48시간 후 확인한다.

### 3주차: 두 번째 사용 유도

첫 결과에서 사용자가 선택한 `미확인` 항목만 다시 보여 주는 링크를 제공한다. 푸시·로그인·뉴스레터 없이 두 번째 방문이 발생하는지 본다. 사용자가 먼저 저장·알림을 요구하는지도 기록한다.

### 4주차: 작은 프로토타입 판정

반복 사건, 질문 사용, 두 번째 방문의 세 신호를 각각 평가한다. 두 번째 방문이 약하고 질문 사용만 강하면 주간 습관이 아니라 상담·시험 기반의 사건형 도구로 포지셔닝한다. 세 신호가 모두 약하면 기능을 추가하지 말고 문제 정의를 다시 조사한다.

## 제품·사업적 의미

반복 사용이 확인되면 학원콕의 제품 정의는 `학원 찾기`에서 `학부모 학습 의사결정 보조`로 확장될 수 있다. 그러나 확장은 학원 품질 평가나 자녀 상태 진단이 아니라, 질문·확인·후속 행동을 정리하는 방향이어야 한다.

반복성만 확인되었다고 곧바로 학부모에게 과금하지 않는다. 무료 점검·질문은 유지하고, 이후 부모가 자발적으로 원하는 저장·비교·상담 후속 정리의 운영 비용과 지불 의사를 별도로 검증한다. 학원 측 수익화는 비순위형 정보 최신화와 비식별 집계 리포트 가설을 유지하며, 부모의 기록이나 상담 내용을 학원에 판매하지 않는다.

## 결정 요청이 필요한 시점

현재는 새 기능을 바로 개발할 단계가 아니다. 먼저 8–10명 대상 반복 사건 인터뷰와 7일 미니 다이어리를 진행한다. 여기서 반복 사건이 확인되면 `점검 → 질문 → 직접 확인 → 다음 점검` 수동 프로토타입을 만들고, 실제 두 번째 사용이 확인될 때만 저장·알림·상담 후속 기능의 구현을 결정한다.

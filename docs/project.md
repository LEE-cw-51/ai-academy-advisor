# 프로젝트 개요

## 이름

AI Academy Advisor (서비스명: 학원콕)

## 목표

학원콕의 상위 목표는 **학부모가 학원과 아이의 학습 상태를 둘러싼 블랙박스를 줄이고, 더 나은 질문과 판단을 하도록 돕는 것**이다.

학부모의 문제는 단순히 좋은 학원을 찾기 어렵다는 데 있지 않다. 바쁜 일상 속에서 아이가 수업에서 실제로 무엇을 경험하는지, 진도·오답·보강·질문 대응·소통이 어떻게 이루어지는지 직접 확인하기 어렵다. 특히 사춘기 학생과의 정보 비대칭 때문에 강사 상담에 과도하게 의존하기 쉬우며, 상담이 충분하지 않을 때는 계속 다닐지·옮길지 판단하기 더 어렵다.

학원콕은 이 불확실성을 없앤다고 약속하지 않는다. 대신 막연한 불안을 **확인 가능한 질문, 출처가 있는 정보, 다음 행동**으로 바꾼다.

## 제품 원칙

> 학원콕은 학원을 대신 선택해 주는 서비스가 아니라, 학부모가 더 잘 확인하고 더 잘 선택하게 만드는 서비스다.

| 원칙 | 의미 |
|---|---|
| 질문부터 | 사용자의 상황과 걱정을 탐색 조건·상담 질문·추가 확인 항목으로 구조화한다. |
| 확인 가능한 정보 | 학원 기본 정보에는 출처와 확인일을 남기고, 확인되지 않은 값은 `null` 또는 미확인으로 다룬다. |
| 사실과 추론의 분리 | 검증된 사실, 런타임 탐색 신호, 상담에서 확인할 점을 구분한다. |
| 직접 판단 | 사용자가 직접 전화·웹사이트 방문·길찾기를 통해 학원과 소통하고 판단한다. |
| 비중개 | 첫 MVP는 등록·예약·결제·상담 접수·부모 연락처의 학원 전달을 하지 않는다. |

핵심 자산은 UI 자체가 아니라 **출처와 확인일을 갖춘 정확한 지역 학원 사실 데이터베이스**다.

## 첫 공개 MVP

### 대상과 핵심 흐름

대상 지역은 하남 미사로 고정한다. 사용자가 현재 다니는 학원 또는 원하는 학원 조건과 고민을 입력하면, AI는 이를 탐색 조건·상담에서 물어볼 질문·추가 확인 항목으로 정리한다. 결과 화면은 출처와 확인일이 있는 학원 기본 정보·지도·공개 연락처와 함께, 왜 후보로 보였는지 및 아직 확인되지 않은 점을 보여 준다.

```text
상황·조건 입력
→ AI의 조건/상담 질문 정리
→ 후보 정보·지도·근거/미확인 항목
→ 사용자의 직접 전화·웹사이트 방문·길찾기
```

### AI의 역할과 표현 원칙

AI는 아이의 상태나 학원의 품질을 판정하지 않는다. `최고`, `확정 추천`, `우리 아이에게 가장 맞음`처럼 단정하지 않고, 결과를 **조건과 관련해 확인해 볼 후보 정보**로 표현한다. 데이터가 없는 수업 방식·오답 관리·고등 연계 정보는 추정해 채우지 않으며 반드시 **상담에서 확인할 점**으로만 제시한다.

기존 `GET /academies`, `POST /recommendations`, `POST /recommendations/ai`는 데이터 탐색과 후보 정리의 기반 계약으로 유지한다. API 응답의 `score`는 같은 응답 안의 상대 순위일 뿐, 별점·퍼센트·신뢰도처럼 표시하거나 저장하지 않는다.

### 첫 MVP에서 하지 않는 것

| 제외 범위 | 이유 |
|---|---|
| 수강 신청, 예약, 결제, 계약 | 학원콕은 첫 단계에서 거래를 처리하지 않는다. |
| 상담 접수 대행, 학부모 연락처의 학원 전달 | 리드 연결과 제3자 제공 구조를 만들지 않는다. |
| 대가성 결과 순위, 유료 상단 노출 | 광고비가 후보 근거나 AI 판단에 영향을 주지 않게 한다. |
| 필수 로그인 | 탐색의 마찰을 낮춘다. 관심 학원 저장·결과 재방문 수요가 검증된 뒤 선택적으로 검토한다. |
| 자녀 실명·생년월일·성적표·상세 자유 서술의 기본 수집 | 초기에는 불필요한 개인정보 및 민감한 학습 정보 수집을 피한다. |

전화·웹사이트·길찾기 클릭은 비식별 행동 이벤트로만 계측한다. 사용자가 공개 연락처를 보고 직접 행동하는 것과 학원콕이 상담을 대신 접수하거나 정보를 전달하는 것은 명확히 구분한다.

## 현재 단계

MVP 단계다. 확장성보다 명확한 구조와 유지보수성을 우선한다. 현재 배포 UI에서 `/`·`/check`·`/checklists`는 소개·점검·체크리스트 퍼널이며, `/app`은 하남 미사 고정의 안내형 추천 화면이다. 실제 공개 탐색 MVP는 위의 질문 우선 흐름을 기준으로 별도 구현·검증한다.

자유 대화형 채팅 및 SSE 스트리밍 채팅(`POST /chat`)은 구현 완료 또는 첫 MVP의 기본 범위로 간주하지 않는다. 로그인/인증(JWT), 관리자 페이지, LlamaIndex 기반 RAG 엔진, LLM 기반 의도 분석도 현재 구현 완료로 보지 않는다.

Phase별 진행 상황은 [roadmap.md](roadmap.md), 이미 내려진 결정은 [decision-log.md](decision-log.md)를 참고한다.

## 단계적 수익화

수익화는 무료 탐색의 유용성과 데이터 신뢰가 검증된 뒤에만 검토한다.

```text
무료 질문/탐색 MVP
→ 데이터 신뢰·반복 사용
→ 학원 정보 최신화·강화 프로필 수요 검증
→ 선택형 상담 예약·리드 연결 검토
```

학원 광고 또는 강화 프로필을 도입한다면 광고 여부를 명확히 표시하고, 학원의 지불 여부가 일반 후보의 순서·AI 근거·추천 논리에 영향을 주지 않게 한다. 상담 예약 또는 리드 연결은 명시적 제3자 제공 동의, 운영 기준, 관련 사업자·개인정보·플랫폼 광고 요건을 별도로 검토한 뒤에만 도입한다.

당근 유료 광고의 심사 요건은 제품의 무료 정보 탐색 구조와 별개로 관리한다. 광고 재개 전에는 ‘무료·무결제·무예약·무상담대행·무리드전달’인 랜딩/서비스 구조를 제시해 필요한 서류·푸터 표기·광고 계정 요건을 서면으로 확인한다.

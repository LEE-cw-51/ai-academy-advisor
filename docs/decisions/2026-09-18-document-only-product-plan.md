# 최신 제출 문서 기반 문서 전용 제품 계획

- 날짜: 2026-09-18
- 상태: 확정
- 범위: 프로젝트 문서만

## 문제

최신 제출용 사업 문서는 학원콕의 핵심을 학부모의 질문을 구조화하고 학원에 필요한 수요 정보를 집계하는 서비스로 설명한다. 기존 저장소 문서는 무료 탐색 MVP와 기술·데이터 안전 원칙은 충분히 설명하지만, 첫 2개월의 검증 목적, 학부모·학원 양면 검증, 사업화 단계 전환 게이트, 창업자의 현직 강사 이해상충을 하나의 인계 가능한 기준으로 모으고 있지 않다.

## 결정

최신 제출 문서의 사업 방향을 프로젝트 문서의 최신 사업·검증 기준으로 반영한다. 다만 이번 반영은 문서 전용이다. 코드, 테스트, API 계약, DB 스키마·데이터, 배포 설정, 환경변수, 외부 서비스 설정은 변경하지 않는다.

첫 2개월의 목적은 기능 확장이 아니라 다음 세 가지를 검증하는 것이다.

1. 상담 질문이 학부모에게 실제로 쓸 만한가.
2. 후보 선정 근거를 학부모가 납득하는가.
3. 학원이 비식별 집계 수요 리포트에 관심을 보이는가.

첫 달에는 후보 근거의 설명 가능성을 문서·운영 관점에서 점검하고, 둘째 달에는 학부모 5~10명 인터뷰와 원장 대상 리포트 시안 검증을 진행한다. 상담 기록·비교·로그인·저장, 유료 리포트 판매, 상담 예약·리드 연결, 인접 지역 확장은 반복 사용·데이터 신뢰·수요·법적/운영 요건을 확인한 뒤 별도 결정한다.

## 이유

최신 제출 문서는 현재 제품을 과장하지 않고, 하남 미사에서 무료 탐색과 질문 유용성을 먼저 검증한 뒤 수익화와 복제로 넘어가는 순서를 명시한다. 이는 기존의 “Build Less, Learn Faster”, 사실과 추론 분리, 비중개·비식별 원칙과 일치한다.

## 영향

- `docs/project.md`는 제품 정의·검증 단계·사업화 게이트·이해상충 원칙을 설명한다.
- `docs/roadmap.md`는 Phase 5c에 1라운드 검증 계획과 단계 전환 조건을 기록한다.
- `docs/data-strategy.md`는 410곳 수량의 기준일 원칙과 비식별 수요 집계 원칙을 설명한다.
- `README.md`는 현재 제공 기능과 후속 검토 기능을 구분한다.
- 동결된 `docs/decision-log.md`에는 새 결정을 추가하지 않는다.

## 하지 않은 것

이번 결정으로 기능이 구현되었다고 간주하지 않는다. 후보 근거 표시, 인터뷰, 리포트 시안, 광고, 결제, 상담 기록은 각각 실제 검증·구현·운영 작업이 필요하며, 문서 반영만으로 완료 처리하지 않는다.

## 다음 작업

다음 구현 또는 운영 작업 전에는 실제 배포 URL, 데이터 행 수와 기준일, 후보 근거 표시 상태를 별도 확인한다. 코드나 데이터 변경이 필요하면 이 문서 전용 결정과 분리된 작업으로 계획·검증한다.

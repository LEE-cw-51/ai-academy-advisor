# 결정 기록

기술·데이터·제품 결정은 이 폴더에 **결정 하나당 파일 하나**로 남긴다
([2026-09-14 결정](2026-09-14-decision-records-per-file.md)).
2026-09-13까지의 결정은 [`docs/decision-log.md`](../decision-log.md)에 그대로 보관한다. 새 항목은 거기에 추가하지 않는다.

> 초기 버전이다. 운영해보고 빠지는 항목이 생기면 그때 고친다. 형식을 강제하는 검사는 두지 않는다.

## 파일 이름

`YYYY-MM-DD-short-english-slug.md` — 예: `2026-09-14-decision-records-per-file.md`

- 날짜를 앞에 둔다. 순번(`0001-`)은 병렬 브랜치가 같은 번호를 만들어 충돌한다. 이름순이 곧 시간순이다.
- slug는 영문 소문자·숫자·하이픈만 쓴다. 한글 경로는 Windows 도구와 URL에서 문제를 만든다. 한국어 제목은 파일 안 H1에 쓴다.
- 같은 날 결정이 여럿이면 slug로 구분한다.

## 최근 결정 찾기

`ls docs/decisions` — 이름순 마지막 파일들이 최신이다. 목차 파일은 따로 두지 않는다(이중 기록 방지).
이 폴더의 결정이 아직 적으면 `docs/decision-log.md` 상단도 함께 본다.

## 템플릿

```markdown
# 제목 (한국어)

- 날짜: YYYY-MM-DD
- 상태: 채택
- 대체: 없음

## 계기

무엇이 바뀌어서 결정이 필요했나.

## 결정

무엇을 하기로 했나.

## 검토한 대안·트레이드오프

## 바꾸지 않은 것

## 하지 않은 것

## 검증·다음
```

- **계기**와 **결정**만 핵심이다. 나머지 절은 해당할 때만 쓰고, 없으면 지운다.
- 도메인에 맞는 절을 더해도 된다(예: 랜딩 퍼널의 `경로`·`계측`).
- **상태**: `제안` · `채택` · `대체됨 → [새 결정](파일)` · `폐기` 중 하나.
- **대체**: 이 결정이 뒤집거나 좁히는 결정. 이 폴더의 파일이면 링크를, 보관 로그의 항목이면
  `decision-log.md 2026-08-14 — 제목`처럼 날짜와 제목을 쓴다.

## 대체 규칙

- 옛 결정의 본문은 고치지 않는다. 그때 무엇을 믿었는지가 이 기록의 가치다.
- 새 결정 파일의 **대체**에 옛 결정을 적는다.
- 옛 결정이 이 폴더의 파일이면, 그 파일의 **상태 한 줄만** `대체됨 → [새 결정](파일)`로 바꾼다.
  옛 파일에서 허용되는 수정은 이것뿐이다.
- 보관 로그(`docs/decision-log.md`)의 항목은 고치지 않고, 새 파일에서 참조만 한다.
